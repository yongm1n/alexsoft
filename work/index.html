OPEN SOURCE · SOFTWARE INTELLIGENCE

코드를 읽어 화면에서 DB 컬럼까지의 지도를 그리는 엔진, Cascade

“이 컬럼을 바꾸면 어떤 SQL, 서비스 메서드, API, 화면이 영향을 받는가.” 오래된 시스템에서 누구도 정확히 답하지 못하던 질문에 소스 코드만으로 답하는 정적분석 엔진을 알렉스소프트가 설계하고 만들어 Apache-2.0으로 공개했습니다. 같은 답이 사람이 읽는 화면과, AI 코딩 에이전트가 직접 물어보는 서버(MCP) 두 곳으로 나갑니다.

성격
오픈소스 정적분석 엔진 · 로컬 뷰어 · MCP 서버Apache-2.0 공개 · github.com/alexsoft-hq/Cascade
답하는 질문
컬럼 → SQL → 메서드 → API → 화면, 양방향 영향 범위바꾸려는 컬럼에서 영향받는 화면까지, 열려는 화면에서 도달하는 컬럼까지
읽는 스택
Java Spring MVC · MyBatis(XML·어노테이션·Plus) · JPA/Spring Data · SQL DDL(MySQL·PostgreSQL·Oracle·H2) · JS/TS·Vue·React 라우터 · OpenAPI · HARKotlin과 GraphQL, 그리고 실행 중에만 정해지는 연결은 읽지 못한다고 밝힙니다
원칙
증명한 것보다 더 주장하지 않습니다확인한 연결과 추정한 연결을 구분해 표시하고, 확인하지 못한 부분은 못 봤다고 적습니다
도입
내 컴퓨터에서만 도는 도구입니다소스와 분석 결과가 밖으로 나가지 않습니다 · 데이터베이스에 연결하더라도 테이블·컬럼 이름만 읽고 데이터는 읽지 않습니다
WHY

변경 영향은 문서가 아니라 사람의 기억에 있었습니다

컬럼 하나를 고칠 때 어느 화면이 깨지는지 확인하는 데 며칠이 걸립니다. 코드를 고치는 주체가 AI 코딩 에이전트로 넓어지는 지금은, 그 질문에 기계가 먼저 답해야 합니다.

HOW

그래프의 모든 선에 등급을 답니다

소스만 읽어서는 알 수 없는 연결은 아는 척하지 않고 못 봤다고 적습니다. 사람이 보는 화면과 AI 에이전트가 받는 답이 같은 엔진에서 나오므로, 둘이 서로 다른 이야기를 들을 일이 없습니다.

SO WHAT

레거시의 영향 범위를 소스로부터 복원합니다

레거시 현대화와 시스템 연동 설계에서 가장 오래 걸리는 일이 ‘어디까지 영향이 가는가’를 알아내는 일입니다. 같은 방식으로 귀사 시스템의 지도를 그릴 수 있습니다.

정적분석이 답할 수 없는 것을 답하는 척하지 않아야, 답할 수 있는 것을 믿을 수 있습니다.

OWN PRODUCT · TEAM GOALS

목표를 다섯 가지 화면으로 보고, 진행률과 마감이 스스로 따라오는 팀 목표 도구, Mokpyo

10–100명 팀의 목표·OKR을 한 데이터 위에서 카드·테이블·보드·타임라인·대시보드로 보여줍니다. 하위 목표의 진행률은 상위로 자동 집계되고, 마감 임박이나 상태 변경 같은 사건에 규칙을 걸면 알림·담당자 지정·상태 변경이 저절로 일어납니다. 알렉스소프트가 2025년 11월부터 직접 설계하고 만들어 온 제품이며, 아래 화면은 가상의 팀과 목표로 채운 데모 워크스페이스입니다.

성격

기술

배포

상태
직접 만들어 쓰는 자체 제품아래 화면은 가상의 팀과 목표로 채운 데모입니다
WHY

목표는 시트에, 진행은 메신저에, 마감은 머릿속에

흩어진 목표를 한 곳에 두고, 팀은 ‘어떻게 볼지’만 고르게 했습니다. 다섯 개 뷰가 같은 데이터를 쓰기 때문에 어느 화면에서 고쳐도 나머지가 함께 바뀝니다.

HOW

화면보다 뼈대를 먼저 세웠습니다

조직별 데이터 분리, 권한과 초대, 누가 무엇을 언제 바꿨는지 남는 기록, 규칙을 실행하는 자동화까지 팀 도구가 갖춰야 할 뼈대를 먼저 설계하고 그 위에 화면을 올렸습니다.

SO WHAT

업무 도구의 품질은 데이터 구조와 권한, 이력이 정합니다

귀사의 내부 시스템과 백오피스도 같은 순서로 설계하고 만듭니다. 화면은 마지막에 옵니다.
