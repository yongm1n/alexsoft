요건을 목록으로 남기는 데서 끝내지 않습니다. 실제 시스템 경계와 데이터 흐름으로 바꾸고, 합의한 범위는 직접 구현합니다.

  1. 01

    EMR·병원 시스템 연동 설계

    진료 흐름과 기존 인터페이스를 기준으로 API, 메시지, 동기화와 장애 경계를 정합니다.

  2. 02

    의료데이터 표준 · HL7 FHIR

    표준 리소스와 현장 데이터의 차이를 분석하고 변환, 버전과 코드 체계를 설계합니다.

  3. 03

    인증·개인정보 대응 아키텍처

    접근통제, 감사, 보관과 폐기 요건이 기능·데이터·운영에 반영되도록 구조화합니다.

  4. 04

    EMR 벤더·신규 팀 아키텍처 자문

    제품 경계, 인증 범위, 개발 순서와 기존 자산을 함께 검토해 결정 기준을 남깁니다.

  5. 05

    병원 IT 현대화

    운영 중인 시스템을 존중하면서 교체, 병행 운영과 단계적 이관의 순서를 설계합니다.

SCOPE BOUNDARY

EMR 제품 전체를 새로 만드는 일은 맡지 않습니다. 이미 있는 시스템과 어떻게 붙일지, 무엇을 표준으로 삼을지, 인증을 어떻게 통과할지를 설계하고, 설계한 것은 직접 만듭니다.

특정 EMR 벤더의 제품 판매를 전제로 하지 않으며, 현재 환경과 표준·교체 가능성을 기준으로 벤더 중립적으로 판단합니다.

인증을 통과한 제품과
운영되는 현장을 함께 봅니다.

알렉스소프트(ALEXSOFT)는 국내 대형 ERP 기업의 의료 사업에서 EMR 인증을 받은 의원급 EMR 중 최초의 클라우드 제품을 개발 리더로 시작해 최근 3년은 개발·기획설계 총괄로 이끌었습니다. 병원정보시스템(HIS) 배경을 바탕으로 제품 기능, 인증과 실제 진료·운영 흐름을 같은 구조 안에서 판단합니다.

자주 묻는 질문

확인할 것들.

어떤 EMR·병원 시스템 연동을 다루나요?+

진료·예약·접수·검사·청구 등 필요한 업무 흐름과 기존 시스템이 제공하는 인터페이스를 먼저 확인합니다. 가능한 연동 범위와 데이터를 정한 뒤 API, 메시지와 운영 절차를 설계합니다.

EMR 인증 대응도 함께 볼 수 있나요?+

인증 항목이 데이터 구조, 기능 경계와 운영 절차에 미치는 영향을 아키텍처 단계에서 함께 검토합니다. 인증 취득 자체를 보증하지 않으며, 적용 기준과 심사 범위는 착수 시 최신 자료로 확인합니다.

특정 EMR 벤더에 맞춘 제안인가요?+

아닙니다. 특정 벤더의 제품 판매를 전제로 하지 않습니다. 현재 사용 중인 시스템의 실제 인터페이스와 제약을 확인하고, 표준과 교체 가능성을 함께 고려해 벤더 중립적으로 설계합니다.

EMR을 직접 만들어 주나요?+

아닙니다. EMR 제품 전체를 새로 만드는 일은 맡지 않습니다. 기존 시스템과의 연동, 의료정보 아키텍처, 인증 대응 설계와 필요한 구현을 맡습니다.

환자·의료기관 자료는 어떻게 다루나요?+

판단에 필요한 최소 범위만 요청하고, 합의한 전달 수단과 보관 기간을 따릅니다. 초기 검토는 비식별 구조와 샘플 데이터로 진행하며 실제 개인정보가 필요하면 접근·처리·폐기 기준을 먼저 정합니다.
