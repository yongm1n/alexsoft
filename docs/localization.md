# 한국어·영어 페이지 유지관리

회사 사이트는 한국어 원본과 전체 영어 번역을 각각 정적 HTML로 제공합니다. 별도 빌드, 서버 언어 협상, 런타임 번역은 없습니다. 영어 페이지는 요약 프로필이 아니라 대응하는 한국어 페이지 전체의 번역입니다.

## 페이지와 공통 파일

한국어는 기존 경로, 영어는 같은 경로 앞에 `/en`을 붙입니다. 홈은 `/`와 `/en/`, 프로젝트는 `/work/`와 `/en/work/`, 글은 `/insights/<slug>/`와 `/en/insights/<slug>/`입니다. 슬라이드도 `/insights/ai-business-website/slides.html`과 `/en/insights/ai-business-website/slides.html`로 짝을 이룹니다.

현재 검사 대상은 16쌍, 32페이지입니다. 홈, 서비스 4개, 프로젝트, Insights 목록, 글 6편, 슬라이드가 검색 대상 14쌍입니다. 404와 네이버 블로그 이동 페이지도 두 언어로 제공하지만 사이트맵에는 넣지 않습니다. `/blog/`는 기존 네이버 채널 이동을 유지합니다.

부산·거제 앱과 각 `about/` 페이지는 한국어 서비스로 유지합니다. 영어 회사 페이지에서도 기존 앱 주소로 연결하며 한국어 서비스임을 표시합니다. 앱에 `/en/` 경로를 만들어 붙이지 않습니다.

| 대상 | 관리 위치 |
|---|---|
| 한국어·영어 본문 | 각 경로의 HTML 파일 |
| 검사할 페이지 쌍 | `scripts/sync-locales.py`의 `PAGES` |
| 공통 헤더·푸터 | `scripts/i18n/header.{ko,en}.html`, `footer.{ko,en}.html` |
| 공통 스타일·언어 동작 | `assets/ink.css`, `assets/ink.js` |
| 내비게이션 스타일 원본 | `scripts/i18n/navigation.css` |
| 번역 검토 당시 한국어 파일 해시 | `scripts/i18n/source-hashes.json` |
| 검색 대상 쌍과 기존 앱 항목 | `sitemap.xml`, `scripts/sync-sitemap.py` |

영어 회사 내부 링크는 영어 경로를 유지합니다. 이미지·영상·CSS 등 공용 자산은 기존 파일을 재사용하고 루트 기준 절대 경로를 씁니다. 외부 원문과 공개 저장소 링크는 원래 목적지를 유지합니다.

## 처음 방문했을 때의 언어 선택

실제 규칙은 `assets/ink.js`가 정의합니다. 자동 선택은 일반 홈 주소인 `/`와 `/index.html`에서만 실행됩니다.

1. 유효한 `lang=ko` 또는 `lang=en` 쿼리가 있으면 이를 사용합니다.
2. 없으면 수동 언어 선택으로 저장한 `alexsoft.language` 값을 사용합니다.
3. 저장값도 없으면 `navigator.languages`를 앞에서부터 읽고 처음 만난 한국어 또는 영어를 선택합니다. `ko-KR`, `en-US`, `en-GB`처럼 지역이 붙은 값도 해당 언어로 처리합니다.
4. `navigator.languages`가 없거나 빈 경우에만 `navigator.language`를 대신 읽습니다. 지원하지 않는 언어들만 있으면 영어를 사용합니다.

예를 들어 `fr-FR, ko-KR, en-US`는 한국어, `en-GB, ko-KR`는 영어, `ja-JP`만 있으면 영어입니다. 배열에 지원 언어가 없다는 이유로 별도의 `navigator.language`를 다시 읽지는 않습니다.

한국어 홈을 명시하는 주소는 `/?lang=ko`입니다. `/en/...`와 한국어 상세 페이지는 저장된 선호나 브라우저 언어 때문에 자동으로 바뀌지 않습니다. 홈에서 영어로 이동할 때는 `location.replace()`를 사용하므로 언어 분기용 방문 이력을 추가하지 않습니다. 뒤로·앞으로 복원(`back_forward`)에서는 자동 이동을 건너뜁니다.

저장은 언어 선택 링크를 직접 누른 경우에만 합니다. 자동 감지 결과나 URL의 `lang` 값은 저장하지 않습니다. 저장소 접근이 막혀도 실제 링크로 이동할 수 있고, 명시적인 한국어 홈 쿼리는 새로고침 후에도 유지됩니다.

언어 선택 링크는 같은 페이지의 반대 언어로 이동합니다. 기존 쿼리는 `lang`을 제외하고 유지하며, 해시가 있으면 같은 섹션으로 이동합니다. 해시 없이 내려 읽던 중이라면 가능한 경우 현재 보이는 섹션의 ID를 사용합니다. 대응하는 섹션 ID를 두 언어에서 유지해야 하는 이유입니다. 이전 `/en/#en-founder` 등 영문 홈 앵커는 공용 스크립트의 별칭으로 현재 앵커에 연결합니다.

JavaScript가 꺼져도 본문과 언어 링크는 정적 HTML로 남습니다. 일반 `/`는 원본 한국어 HTML을 표시하며, 사용자가 `/en/` 링크를 눌러 영어를 읽을 수 있습니다. 자동 선택과 읽던 위치 추정은 JavaScript가 있을 때만 동작합니다.

## 본문을 수정하거나 새 페이지를 추가할 때

1. 한국어 원본의 변경 범위를 확인한 뒤 대응하는 영어 본문을 직접 번역합니다. 문단, 목록, 표, 다이어그램, 캡션, 대체 텍스트, 제목·설명 메타데이터, JSON-LD, FAQ, 폼 안내와 스크립트 메시지까지 확인합니다. 승인된 주장·수치·시점·출처와 이미지의 원본은 유지합니다.
2. 새 글은 한국어·영어 HTML을 함께 만들고 두 Insights 목록을 갱신합니다. 글의 `*/index.html`은 페이지 목록에 자동 포함됩니다. 그 밖의 새 경로는 `PAGES`에 추가합니다. 기존 페이지를 덮어쓰는 자동 번역 기능은 없습니다.
3. 공통 헤더·푸터와 언어 메타데이터를 정규화합니다.

   ```bash
   python3 scripts/sync-locales.py
   ```

   이 스크립트는 현재 존재하는 페이지의 공통 영역, 언어 링크, canonical·hreflang·OG·구조화 데이터 언어, 공통 자산 참조를 맞춥니다. 본문을 번역하거나 없는 영어 페이지를 생성하지 않습니다. 따라서 실행 성공만으로 번역이 완료된 것은 아닙니다.

4. 사이트맵의 한국어 원본 항목과 실제 수정일을 확인한 뒤 언어 쌍을 동기화합니다.

   ```bash
   python3 scripts/sync-sitemap.py
   python3 scripts/sync-sitemap.py --check
   ```

   새 영어 항목을 처음 만들 때는 `--new-date YYYY-MM-DD`에 실제 준비 날짜를 지정합니다. 이 옵션은 새 영어 항목에만 적용합니다. 기존 한국어·영어 항목의 `lastmod`는 자동으로 오늘 날짜로 바꾸지 않으므로, 실제 편집한 페이지의 날짜는 별도로 갱신합니다. 원래 글의 게시일을 번역 준비일로 바꾸지 않습니다.

5. 한국어와 영어의 의미·수치·범위를 사람이 대조하고, 실제 브라우저에서 양쪽 언어의 화면과 기능을 확인합니다. 그 검토가 끝난 후에만 현재 한국어 원본의 해시를 기록합니다.

   ```bash
   python3 scripts/check-locales.py --record-reviewed-sources
   python3 scripts/check-locales.py
   node --test tests/locale.test.cjs
   ```

   `--record-reviewed-sources`는 번역하지 않습니다. 검토가 끝난 한국어 파일들의 전체 SHA-256을 `scripts/i18n/source-hashes.json`에 기록합니다. 메타데이터와 스크립트 참조도 해시에 포함됩니다. 이후 검사에서 원본 변경 경고가 나오면 변경분을 읽고 영어 반영 여부를 판단한 뒤 다시 기록합니다. 경고만 없애려고 먼저 기록하지 않습니다.

`scripts/check-locales.py`는 현재 32페이지·16쌍의 구조와 ID, 대응 링크, 메타데이터, 공통 영역, 영어 페이지의 한국어 잔여 문구, 폼 전송 계약, FAQ 본문과 JSON-LD, 자격 배지, 원본 해시를 검사합니다. 검사는 번역의 의미를 판단하지 않으므로 본문 대조를 대신하지 않습니다.

## 로컬 브라우저 검증

로컬 서버와 실제 Chrome을 사용합니다. 사이트에 빌드 도구나 브라우저 자동화 라이브러리를 추가하지 않습니다.

```bash
python3 -m http.server 8074 --bind 127.0.0.1
```

다른 터미널에서 실행합니다.

```bash
QA_ORIGIN=http://127.0.0.1:8074 node tests/browser-locales.mjs
```

기본 Chrome 경로가 다르면 `CHROME_BIN`에 실행 파일 경로를 지정합니다. 검사는 임시 Chrome 프로필을 사용하며 새 방문자의 언어 우선순위, 수동 전환과 저장, URL·섹션·쿼리 유지, 새로고침·뒤로·앞으로, 저장소 차단, 320·390·1440px 화면, 이미지와 JavaScript 비활성 상태를 확인합니다. 결과와 화면 캡처는 `.private/qa-bilingual/`에 남습니다. 캡처는 직접 열어 글자 겹침과 도표 잘림도 확인합니다. 문의 폼을 실제 제출하는 검사는 아닙니다.

## 폼·경력·검색 정보의 유지 기준

문의 폼은 표시 문구만 번역합니다. `entry.*` 필드명, Google Forms 전송 주소, 선택지의 `value`, 숨은 관심 분야 값, `data-inquiry-type` 등 한국어 원본의 전송 계약은 유지합니다. FAQ는 화면 질문·답변과 해당 언어의 JSON-LD를 함께 고칩니다.

경력은 대표 이용민의 역할과 참여 기간으로 서술합니다. EIS 전체 사업은 2018–2022년, 대표의 개발 PL 참여는 2020–2022년입니다. EMR은 2022년 개발 리더, 2023–2026년 개발·기획설계 총괄입니다. Mokpyo의 2025년 11월 개발 시작을 회사 운영 시작으로 표현하지 않습니다. AWS 정식 자격명, 공식 배지와 Credly 링크를 유지하고 취득일·최근 취득 문구나 삭제한 보유자 설명 줄을 다시 넣지 않습니다.

각 언어 페이지의 canonical은 자기 URL입니다. 홈의 hreflang은 `ko` → `/?lang=ko`, `en` → `/en/`, `x-default` → `/`입니다. 상세 페이지의 `ko`와 `en`은 서로의 정식 주소를 가리키고 `x-default`는 영어 주소입니다. 사이트맵도 같은 세 주소를 양쪽 항목에 넣습니다.

사이트맵 동기화는 한국어 원본 항목의 이미지·영상 메타데이터를 보존해 영어 짝을 만들고, 영어 영상 제목·설명은 해당 영어 페이지의 `VideoObject`에서 읽습니다. 기존 영어 홈의 제품 갤러리·영상 목록을 계속 보존하지는 않습니다. 현재 대응 페이지를 기준으로 맞추므로 Cascade 영상은 `/work/`와 `/en/work/`에 속합니다. 독립된 부산·거제 앱 항목은 그대로 유지합니다. 이 작업은 기존 한국어 사이트맵의 미디어 목록을 전면 정리하지 않습니다.

이 절차는 로컬 수정과 미리보기까지입니다. 검증 통과는 배포나 검색 색인 완료를 뜻하지 않습니다. 커밋·푸시·공개 배포는 별도로 요청받은 범위에서 진행합니다.
